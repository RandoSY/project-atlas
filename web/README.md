# Project Atlas on the web

The twelve generated static pages under `web/atlas/` are ready to serve at `/atlas/`. They reuse the live calculus page's stylesheet. The recovered Water Clock model is a separate standalone HTML file.

The Idea Index and Project Inventory are rendered from the canonical Markdown at the root of this repository. Their off-GitHub sections are deliberately omitted from the rendered site. The full repository browser uses a snapshot of GitHub's public listing, distinguishes forks, and adds historical project homes from the legacy map. Only the generated `web/atlas/` directory belongs in the Nginx web root.

## Rebuild on a PC

Install Python 3 and Pandoc. From the repository root, run:

```sh
python3 web/build_atlas.py
```

To refresh the public repository snapshot as part of the rebuild:

```sh
python3 web/build_atlas.py --refresh-repos
```

Review the changes to the public snapshot and generated HTML before committing. The IONOS host does not need to run the generator, install any runtime, or hold GitHub credentials.

## Local check

```sh
python3 -m http.server 8000 --directory web
```

Open `http://127.0.0.1:8000/atlas/`. The CORE 10 and first-page downloads link to their existing original copies on GitHub rather than creating new copies. The calculus link stays on the current origin and expects the separate calculus site at `/calculus/`. The standalone preview serves Atlas only.

## First install on the existing IONOS VM

Use the same authenticated Linux shell and Nginx web root that serve `/calculus/`. The commands in the handoff download the reviewed commit as a GitHub archive and extract only `web/atlas/`. They verify the expected calculus file and the staging files before moving the new directory into place. The first-install command stops if `/atlas/` already exists on disk. No Nginx reload or configuration change is needed, and the calculus directory is not changed.

For later revisions, build in GitHub first, stage a new directory beside the current Atlas, and retain the previous directory outside the web root until the new version and its links are verified.


## Virtual Instruments

The home-page feature leads into five build guides and a gallery of real browser captures. The gallery captions and original source names are in `capture_catalog.json`. The public copies are WebP images, not the original device-control HTML. Most captures were freshly rendered from the original interfaces with no bench device attached. The archived UNO Q reference screenshot is identified separately.

The guide is authored in `instruments.html`; the generator inserts the capture catalog and writes `atlas/instruments/index.html`. Treat illustrative pin assignments as starting points, not tested builds or replacements for the board documentation.


## The Singing Rule

The flagship exhibit uses the original apparatus photo and detail crops, two archival dashboard views (browser chrome cropped), the archived Spring Mass Lab screenshot, and four plots from the recovered analysis archive. See `singing-rule-media.json` for each source filename and treatment. The raw sensor CSV was not in the recovered bundle.

Edit `singing-rule.html` for the exhibit or `atlas/assets/singing-rule.js` for the browser model. The model is explicitly illustrative. Its frequency and decay are not fitted to the measured run.


## SQM+ Hallway Observatory

The hallway exhibit separates timed course speed, acquisition and transport integrity, and candidate-step validation. It uses the supplied one-hallway illustration and ready screen, selected dashboard and device-state captures, and a publicly licensed reference replay. Image sources and treatments are listed in `sqm-plus-media.json`. No personal walking times, counts, raw trials, LAN identifiers or device-control code are included. The interactive candidate calculator uses invented values. The acceptance worksheet is blank.

Edit the exhibit body in `sqm-plus.html` and regenerate the static site with `python3 web/build_atlas.py`.


## Atlas navigation and the Exhibits gallery

The top navigation has five page links: Home, Exhibits, Ideas, Projects, and Repositories. The homepage gives the Singing Rule the large feature, with smaller entry points for SQM+ and Virtual Instruments. The Exhibits gallery links to the existing exhibits, CORE 10, and the separate calculus site. Individual exhibit URLs stay unchanged.

The gallery and homepage are generated by `build_atlas.py`. Project families are listed with the Project Inventory. The shared navigation and card layouts are in `atlas/assets/navigation.css`.


## Pop-Can Calorimeter

The CORE 10 exhibit distinguishes the measured candle-only mass-loss endpoints, the archival apparatus and PicoScale illustrations, and the newly authored rate-profile model. A paired water-heating time series is not represented as recovered. Photo and illustration sources are in `pop-can-media.json`; the blank worksheet remains separate from the archival data.

## Start Here guide

The home-page callout above the Singing Rule links to `/atlas/start-here/` and a two-page printable PDF. Edit `start-here.json` to update the first stops, site map, exhibit descriptions, and CAP guidance in both editions. Rebuild the web page with `python3 web/build_atlas.py`. Rebuild the PDF with `python3 web/build_start_here_pdf.py` using ReportLab and the DejaVu and Liberation fonts listed in that script. Serve both from the generated site.

## Galileo’s Water Clock

Author the exhibit text in `water-clock.html` and rebuild the site. The public assets preserve the experiment’s design and materials without claiming a measured run:

- `atlas/water-clock/Water-Clock-Lesson-v0.2.pdf` is the web-optimized edition of `CORE10_Galileos_Water_Clock_Illustrated_Lesson_and_Dashboard_Guide_v0.2.pdf`. The apparatus image is a raster export of page 3.
- The dashboard image is from `dashboard_live.png`, cropped to the controls and demo data, omitting the original status/IP strip.
- `SDL_ATOM_Water_Clock_v0.2.zip` is the original source package. Both Wi-Fi configuration values are blank. The package is a bench-test candidate, not a hardware-validated release.
- `model.html` is adapted from `The_Changing_World_Interactive_Calculus_Lab_Tabs.html`. Atlas adds a return link, initial-tab fragments, and narrow-screen styling. The model and CSV computations are unchanged.
