# Public Project Recovery Census

**Deep-recovery control list — 15 September 2026**

This census exists so a project cannot disappear merely because a folder, conversation title, or old repository name is forgotten. It is derived from the surviving master catalogs, architecture documents, public GitHub repositories, and Library artifacts.

**Boundary:** IAS / Independence Assurance and closely coupled private assurance/medication material are deliberately omitted from this public census. Their omission does **not** mean they are forgotten; they require protected off-GitHub preservation.

Status words here describe **recovery status**, not technical validation.

- `CANONICAL` — already has an intentional canonical GitHub home.
- `SOURCE FOUND` — one or more strong source artifacts have been located.
- `LINEAGE FOUND` — historical documentation/repository evidence exists.
- `FORENSIC TARGET` — named and understood, but source package still needs recovery.
- `UPSTREAM` — third-party material/reference; preserve attribution rather than claim authorship.

## 12. Forensic search rule

A `FORENSIC TARGET` is not presumed lost. Search in this order:

1. exact filename from old architecture/source-trail documents;
2. Library title and content search;
3. old GitHub repositories and commit trees;
4. ZIP/release packages and generated manuals;
5. screenshots only as evidence of existence/interface when source is unavailable;
6. finally, record the item as `MISSING ARTIFACT — EXISTENCE DOCUMENTED` rather than silently dropping it.

This census is expected to grow during recovery. It is intentionally broader than the active development portfolio.
