# Project Atlas

**Front door to the Rando Young Intellectual Estate**

Project Atlas is the authoritative public map for this body of work in physical computing, science and engineering education, measurement, robotics, human performance, embedded tools, and AI-assisted laboratories.

The governing questions are: **How much? Enough?** Measure reality, then judge sufficiency against a purpose.

The estate is **not a file backup. It is an idea backup.** Files, repositories, manuals, code, comics, experiments, and validation records are evidence containers whose purpose is to preserve enough meaning for the work to survive its original author.

## Governance

This estate is a curated working exhibition and source trail, not a dump. Each durable system should have one canonical name, one canonical home, an honest lifecycle state, a known-good proof when one exists, and a clearly stated next action.

A project is not considered preserved merely because its source or PDF exists. The estate should retain its problem, central idea, rationale, mechanism, distinctive contribution, evidence, conceptual evolution, limitations, and reconstruction path.

Lifecycle labels are `active`, `validated`, `incubator`, `archived`, `upstream`, and `proprietary / off-GitHub`. Source, evidence, and presentation should remain distinguishable.

## Architecture

**CORE** contains the technical and educational foundation: SDL / SUPER / MCP, CORE 10, and the Measured Machine line of Nugget, observatories, simulators, tools, and robotics.

**APPS** applies transparent measurement to human and personal decision problems: FFT, SQM+, Tone Trainer, and PlateLab. Shared infrastructure should be extracted rather than duplicated.

**TRANSMISSION** turns the work into something another person can inherit: Project Atlas, guides, manuals, papers, experiment packages, visual explainers, and comics.

## Protected boundary

**IAS — Independence Assurance System — is intentionally off-GitHub.** It is not part of this public repository estate.

## Recovery priority

When time or storage is limited, preserve in this order:

1. unique ideas and design rationale;
2. canonical explanations and architecture;
3. representative working source/executable artifacts;
4. validation evidence and experimental data;
5. teaching material and visual explanations, especially comics;
6. historically meaningful versions showing conceptual evolution;
7. duplicates only when needed for provenance or reconstruction.

## Working principles

- **How much? Enough?**
- **Experience Before Equation**
- **Need Before Technology**
- **Not talk, do**
- Prefer durable ideas over particular platforms.
- Preserve broadly; publish selectively.
- Name behavior clearly.
- Explicit failure is better than plausible-looking invalid data.
- Do not call copied material verified until its minimum working path has actually been reproduced.
